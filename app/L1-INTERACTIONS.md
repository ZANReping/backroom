# L1 箱顶、地图与手部切换

本轮实现用户要求的四项修改，保留 C、D 阶段更新和现有工作区内容。当前目标仍为单人 Three.js 游戏。

- **L1 补给箱可站立。** 合批后的板条网格不再覆盖箱体的支撑语义。碰撞使用与模型相同的 `L1_CRATE` 尺寸、摆放中心和旋转；单箱顶为 0.68 米，双箱顶为 1.36 米，侧面仍阻挡。转角处用真实旋转后的矩形轮廓，不把外接矩形的空角当成地板。双箱仍需从合适高度抵达，不改变玩家跳跃能力。
- **快捷栏手部切换。** 使用约 0.22 秒的压低、换物、抬回动作；在最低点更换已有缓存模型，连续切换追随最新选项。数字键、滚轮、点击和触屏快捷栏共用相同的选择状态。攻击、消耗品使用、收起主手和暂停优先，动画不增加冷却或改变物品结算。状态仅在渲染器内存中，不写入存档。
- **L1 大小地图。** 天鹰、跃金、哥特、衔尾、花园、小径、传说段分别使用配色及图形符号，真实墙柱和门洞来自当前建筑数据；积水使用与画面相同的水洼形状。金属门区分关闭实线和打开虚线。大地图补充区域及墙柱、门、积水、容器、掉落物、出口、据点图例；小地图保持简洁，不在下方追加图例。沿用玩家方向箭头、受遮挡的视野和原有交互。
- **尸体闭眼。** Object 70 的新鲜及腐败阶段复用现有 `neutral-blink.png`，在静态模板烘焙前固定为闭眼。白骨阶段维持原有颅骨；活体 NPC 和玩家继续使用各自的睁眼及眨眼贴图。没有增加新图片或修改原资产许可。

地图的实时窗口使用不可变建筑数据缓存。读取远处地图时由现有 Worker 返回建筑二维记录，不构造 Three.js 场景或生成物资、NPC、实体。普通地图只请求已探索的远处区块，并逐格裁切迷雾；开发者地图全开才显示未探索地形。预览不修改探索位图或运行世界，右键安全传送仍使用原有入口。

本轮未修改世界生成版本、烘焙修订、物品身份或存档格式。联机继续封闭。

## 验证与复现

在 `app` 中运行：

```powershell
npm run check:l1-interactions
npm run check:object70
npm run check:l1-props
npm run check:seating
npm run build
npm run verify:l1-interactions
npm run verify:l1-interactions -- --classic
```

实际 App 验收使用种子 `20261006`、1080p、独立内存存档、专属服务端口和浏览器 profile，启动参数为 `--headless=new`。原生 GPU、截图、短动画取帧、运行检查结果和未验证范围见 [验收记录](reports/l1-interactions/README.md)。快捷栏动画图由实际游戏逐帧复制为三个画格，并未使用独立示例模型。

`--before` 只供本次已经保存的源码快照生成基线：必须存在 `.cache/l1-interactions/baseline.json` 及对应旧文件。正常的修改后验收不依赖这些快照，不会回退或覆盖生产源码。
