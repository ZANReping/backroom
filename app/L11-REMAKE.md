# Level 11 城市重制

本次实现位于 `app` 的 Three.js 单人游戏。设定与画面依据 [Level 11 中文维基](https://backrooms-wiki-cn.wikidot.com/latest:level-11)及 `reference/L11/` 的九张参考图；无人城市、六盘磁带档案馆入口和任务暂停规则采用本次确认的游戏方案。

## 生成与空间

`src/game/world/l11Layout.ts` 生成版本 3 的 `L11CityPlan`。宏区为 1024 米，加载区块为 32 米，沿用 5×5 区块的无限地图窗口。宏区坐标以 16 米为偏移，边界主干道与 512 米片区道路确定性衔接。所有随机决策来源于世界种子和空间键，不依赖请求或加载顺序；原有 `l11v2` 实例 ID 保持稳定。

生成顺序为地形与运河 → 主次道路及桥梁 → 街区多边形 → 建筑地块 → 剩余空间巷道 → 按用途陈设。地形为平地和缓坡；运河由全局连续曲线采样，具有驳岸、步道、护栏、水闸设施。四种片区朝向形成网格、斜路和滨水弯道；多中心密度场决定高度和用途分布。公园承担城市绿地。

道路与岸线经 `polygon-clipping` 裁切得到街区；建筑地块保留退界和约 4 米的服务间距。地块支持庭院、转角、双塔裙房、退台及其他组合体量。巷道来自建筑占地以外的街区空间，服务道具限于一侧靠墙范围。道路人行区域、桥面与水岸从相同规划轮廓生成。

`l11Types.ts` 的规划、建筑、道路、桥梁和区块数据通过 `l11.worker.ts`、`l11ChunkCache.ts` 和 `infinite.ts` 传递。版本参与缓存键，建筑、道具、出口和容器具有稳定空间标识。跨区块建筑由加载窗口引用计数及渲染实例表管理；桥面、岸线和道路按区块裁切连续铺设，不依赖单一区块拥有完整模型。

`l11Collision.ts` 提供旋转建筑外墙、门洞、庭院入口、内墙、立柱和道具部件的多边形碰撞。渲染、地面高度、楼梯和碰撞共用建筑描述。小地图视线也使用轮廓，避免斜向建筑的矩形空气墙；不可进入建筑的窗面为深色不透明材质。

## 建筑与装饰

`content/l11Buildings.ts` 登记五组基础结构原型，共 32 种：

| 类别 | 原型 |
|---|---|
| 住宅 | 板式公寓、阳台公寓、围合庭院、转角住宅、联排住宅、独立住宅 |
| 办公 | 幕墙塔楼、横窗板楼、竖肋混凝土楼、石材退台楼、圆角办公楼、双塔裙房 |
| 商业 | 雨棚排铺、街角商住、庭院商业、超市、停车楼、城市旅馆 |
| 工业 | 锯齿顶厂房、砖砌厂房、装卸仓库、小型车间、变电站、泵站／水闸房、未完工混凝土楼（9–15层）、铁栅窗砖楼（3–5层） |
| 公共 | 档案馆、学校、博物馆、体育馆、交通站、市政服务楼 |

开放状态独立于原型选择。种子 42 和 20261006 的 2052 个区块抽样包含 680 座建筑，457 座开放（67.2%）。开放建筑中 305 座开放首层、131 座开放两层、21 座开放三层，分别为 66.7%、28.7%、4.6%。上部封闭楼层保留明确的深色窗面表达。

`content/l11Decor.ts` 登记尺寸、碰撞、放置区域及交互／容器属性，再由 `l11*Parts.ts`、模型构建器、装饰设计模式和生成器使用。100 个新原型均为静态陈设，分类为交通市政 20、街道商业 20、滨水绿化 15、附属施工 15、室内 30；搜索使用已注册的储物柜容器，保留现有搜索与搜刮流程。车辆为静态道具。商业街采用多组门前设施，室内按用途布置家具并留出入口、楼梯及中央通道。

建筑近、中、远距离模型分别在 0、65、150 米切换；远景轮廓由同一城市规划产生。模块按材质合批，复用 PBR 材质；近距离室内陈设采用带滞回的距离裁剪。新增建筑和道具为项目原创参数化几何。复用纹理的作者、原始页面、准确许可、本地路径及加工记录见 [L11-ASSET-SOURCES.md](public/textures/L11-ASSET-SOURCES.md)。

城市材质不使用噪点纹理。十二套表面纹理来自 ambientCG 的 CC0 资产，草地采用 Grass004 的颜色、OpenGL 法线和粗糙度图，按 1.4 米周期平铺；漆面与玻璃使用纯色 PBR 参数，异步加载占位仅使用单色像素。L11 内复用的储物柜也采用 CC0 金属材质。素材选择顺序为适合的 CC0 资产优先，无法满足时再使用图片生成技能；标牌按用户后续明确要求单独使用图片生成技能制作。

新增 32 块 **00 年代风格的完整标牌**，不是独立标志。整块牌面的中英文名称、图案、底色、边框均来自内置 `image_gen`；含店招、小区与商务楼铭牌、公共建筑牌、工业设施牌、街道名牌、公交与停车设施、层级出口和地铁指引。原图和全部提示词保存在 [assets/l11-signage](assets/l11-signage/FULL-SIGN-PROMPTS.md)，可用 `node scripts/prepare-l11-signage.mjs` 重建图集。

`content/l11Signs.ts` 与 `l11SignAtlas.json` 先登记牌面及建筑用途映射，再由 `renderer/l11Signs.ts` 添加到已有注册模型，不把换牌面重复计入 100 种装饰原型。品牌由建筑种子稳定选择，街道名牌按道路 ID 选择，同一路段的两侧和重新加载后保持一致。道路名牌和入口指引双面朝外、各面字向正常；商业牌位于雨棚前沿并保留步行净高。32 种牌面共用材质和合批，颜色图集提供 4096×2048、2048×1024 两档；切换质量同步更新引用和释放旧贴图。

城市保持白天，提供晴朗、多云、阴雨、薄雾。真实光照使用天空环境、阴影、PBR 与后期处理；经典光照及低画质路径保留。低画质验证使用 8 个场景灯、关闭阴影和泛光、低纹理、0.55 细节距离。

## 出口、任务和旧存档

- 首都、新时代广场、Beta／琥珀营的生成入口、地图标记、常驻 NPC 和开发传送选项已移除。L11 不生成人类 NPC，保留无面灵、猎犬、死亡飞蛾、钝人和安抚效果。

- 稀有建筑出口：

| 位置与触发物 | 去往 |
|---|---|
| 封闭混凝土空壳楼门 | Level 1 |
| 开放混凝土楼裸露电梯井步入 | Level 2 |
| 砖墙木门铁栅窗楼门 | Level 3 |

每个宏区每类最多 1 个、每街区最多 1 个，中心间距至少 180 米，宏区边缘保留 120 米；两处道路出口间距至少 90 米。

烂尾楼柱、梁、楼板、核心筒与电梯井复用 L1 裸混凝土的 CC0 Concrete034 三通道纹理，保持 .32 次/米的物理 UV、.24 法线强度和 .86 粗糙度；不引入噪点或 L1 室内烘焙光。砖楼临街宽度至多 13 米，按参考图保留左侧小木门与右侧大铁栅窗；特殊原型仅由稀有出口规划器选取。门体、井壁与模型共用碰撞描述。

- `city-lesson`、`suburban-margin`、`harvest-caution`、`shelter-chain`、`unfinished-atlas` 停止发放与推进。已接任务显示暂停，不计入同时进行上限；完成记录和既得奖励保留。
- M.E.G. 晋升门槛改为 2、5、9、11；其他团体仍为 2、5、9、13。已获得职级保留。

`engine/l11Migration.ts` 在修改旧快照之前，将完整原始 JSON 写入同一 `localStorage` 的 `<原存档键>_l11_v1_backup_<内容哈希>`，并读回逐字校验。备份失败时保持原槽不变并阻止本次加载后的自动覆盖；腾出浏览器存储空间后可重试。备份键可在浏览器开发工具的 Application → Local Storage 中导出留存。

迁移只重建 `L11WorldSave` 的地图、探索和场景状态，保留角色、物品、磁带、任务、奖励、团体职级及其他层级数据。`L11WorldSave` 仍为版本 2；停留在旧 L11 或 Beta（内部编号 115）的角色迁到新安全入口。版本 2 再次加载不重复迁移。装饰的离开后变化只影响外观，建筑、道路、出口和已搜刮容器账本保持稳定。动态区块／探索保存有 600 区块上限，搜刮容器账本独立保留。

生成版本 3 的出口扩展已通过多种子生成、32 建筑／108 装饰模型检查、生产构建和独立无头 Chrome 实机验证。实际进入 L1／L2／L3／L4／L601，检查了楼梯、井口步入、磁带不足、六盘消耗、二次交互与存读档。最终材质和门窗位置截图、执行命令、范围限制及清理证据见 [出口扩展验收报告](reports/l11-exits/index.html)。下方其余数量与性能结果保留为旧版本验收记录。

### 2026-10-13 验收结果

上述静态检查、TypeScript 检查与生产构建通过。模型检查覆盖 969 个几何对象，并确认逐个释放；目录所有原型与各级 LOD 合计 1,512,689 个三角形，此数值不是单帧绘制量。构建仍提示既有字体 URL、PostCSS `from` 和较大产物分包警告，详见 [build.log](reports/l11-remake/build.log)。

最终完整真实光照运行的 [realistic-runtime.json](reports/l11-remake/realistic-runtime.json) 为 `ok: true`，浏览器控制台及运行错误列表为空。实际游戏完成上表的通行、出口、搜刮、迁移、任务、Worker 和资源检查。经典光照与低画质的完整功能检查也通过，分别记录于 [classic-runtime.json](reports/l11-remake/classic-runtime.json) 和 [low-runtime.json](reports/l11-remake/low-runtime.json)；这两次运行发生在最终完整标牌接入之前。最终标牌在三档均另行验证，最新经典／低画质证据为 [classic-signs-runtime.json](reports/l11-remake/classic-signs-runtime.json) 与 [low-signs-runtime.json](reports/l11-remake/low-signs-runtime.json)，均无运行或控制台错误。

早期完整经典／低画质检查的移动中位数／P95 分别为 37.5／95.9 与 8.4／54.2 毫秒；当时曾观察到其他程序占用大量 GPU，证据保留于 `hardware-load.json` 和 `hardware-device.csv`。后续 `hardware-load-signage.json` 中已不再出现相同的外部主负载，故不能将最终 429.2 毫秒长帧归因于早期负载，也不据早期数字比较三种模式的性能高低。未关闭用户程序。

最终三次卸载／重载后的计数完全一致：408 个几何、57 张 GPU 纹理、70 个着色器程序、7 个建筑实例／引用、33 个资源根；待编译、待释放及待加载队列均归零。五次高低纹理切换中，真实光照纹理计数稳定地在 53／56 之间切换，经典光照保持 38，低画质路径在 42／45 之间切换，回到原档后恢复原计数。此处是 Three.js 资源数量，不是显存字节测量。
