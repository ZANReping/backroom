# Level 11 装饰物、UV 与摆放细化

本轮限定 `app` 的单人 Level 11。100 种既有原型沿用注册 ID、设计模式入口和非容器属性；可搜刮储物柜仍由原有系统管理。城市道路、建筑、出口、建筑种子和储物柜搜刮 ID 不因装饰版本改变。

## 模型与材质

- 全部道具改用以米为单位的局部 UV。箱体分面展开，圆柱侧面按周长展开、端面平铺；圆环按环长与管周长展开。零件旋转后 UV 随模型一起转动，不把整张纹理压进每根细杆。
- 家具木纹采用 CC0 Wood051；施工托盘、木箱、电缆盘采用浅色 CC0 Wood092。板材按长轴对齐木纹，分别兼容原始扫描的 U / V 纹理方向。织物采用 CC0 Fabric061，颜色、法线和粗糙度使用同一重复尺寸。
- 区分织物、橡胶、纸张、塑料和瓷器的表面参数。沙发、扶手椅、床垫与办公椅软垫使用圆角几何；玻璃展柜、灯罩、电话亭、候车亭使用独立玻璃面。
- 补充售货机内部货架与饮料、报刊箱堆叠纸张、电话听筒和按键、购物车网篮、带支撑的自行车货架与轮辐、车辆轮毂和灯具等结构。
- 修正井盖、炉圈、喷泉、救生圈、绞盘、绝缘子、自行车轮、线缆盘等部件的轴向；补齐托盘分层、货箱板缝、空调风扇、脚手架斜撑和装卸平台踏步。
- 渲染与碰撞使用一致的 XYZ 旋转约定，支持零件的 Y 轴旋转和锥形圆柱外扩尺寸。透明薄面不生成额外空气墙。

运行时共使用 15 套 CC0 PBR 表面，保持高低质量档、mipmap、材质复用与合批。没有新增噪点纹理。32 张完整的 2000 年代风格标牌继续使用原有图集。来源、作者、许可证、物理尺寸、原始文件和加工记录见 [资产来源](public/textures/L11-ASSET-SOURCES.md)。

## 摆放

- 所有原型正面统一为局部 `-Z`。道路两侧的设施、候车亭朝道路，车辆按两侧车道采用相反行驶朝向，信号灯朝向来车。
- 桌椅成组，椅子朝向对应桌面；柜体、床头、暖气片和黑板按实际建筑轮廓靠墙并面向室内，支持斜向楼体和庭院边界。暖气片与黑板登记安装高度。
- 家具生成之前为可搜刮储物柜预留空间，避免柜体与沙发等模型重叠；继续避让入口、楼梯、分隔墙和主通道。
- 店前咖啡椅朝桌面，滨水长椅朝运河；后巷设施按深度贴近外墙，检查前方通行空间。
- 井盖和雨水篦子共用路面高度常量，表面露出路面、下部嵌入；井盖避开中线标记。
- 室外放置检查完整旋转轮廓，避让建筑、门口、水面和地铁坡道。装饰版本加入 Worker 缓存键，不提升城市规划或存档版本。

## 验证方法

在 `app` 下运行：

```powershell
npm run build
npm run check:l11
npm run check:l11-surfaces
npm run check:l11-meshes
npm run check:l11-dressing
npm run check:l11-props
npm run verify:l11 -- --props
npm run verify:l11 -- --props --resources
node scripts/l11-prop-contact-sheet.mjs
```

`check:l11-props` 检查 100 种原型、度量 UV、原木纹理方向、三轴旋转、斜杆端点、渲染顶点与碰撞轮廓、圆环轴向、靠墙方向、储物柜避让，以及多个种子、负坐标与宏区边界的实际摆放。`check:l11-dressing` 在两种种子共 2052 个区块中检查全部原型仍能生成。

`verify:l11 -- --props` 使用独立端口、独立浏览器配置目录和真实 `--headless=new` Chrome，固定种子 20261006、1920×1080、真实光照档。27 个道具近景均来自实际生成的游戏世界，新增 `storm_drain`，拍照位置通过真实玩家碰撞检查；不插入展示模型。接着验证 Worker 一致性、室内与楼梯通行、地铁、水岸、磁带入口、搜刮、存读档、迁移、跨区步行和三轮卸载重载。

资源检查分别记录场景 CPU 几何、已上传 GPU 几何和场景外 GPU 计数，避免把隐藏内饰的延迟上传误判为泄漏；三轮检查仍要求模型、纹理归属和跨区建筑引用稳定。

经典和低质量档可用 `--props-only --prop-filter=bus_shelter,pallet_stack,life_ring,sofa,bed,office_desk,exhibit_case` 快速复核相同道具及全部材质通道。完整截图、控制台错误、帧时间、浏览器/显卡型号和清理记录保存在 [reports/l11-props](reports/l11-props)。静态检查与真实运行结果分别保存，第一轮视觉问题及其截图保存在 `iteration-1`，最终验收结果见同目录 `RESULTS.md`。

## 滨水细化（参考版本 13）

当前目录为 103 种装饰原型。新增 `l11_quay_balustrade` 石柱滨水栏杆，尺寸 4×0.5×1.1m，无交互、非容器。原 `l11_canal_railing` 保留给桥上和其他岸道；步行岸道使用石柱、压顶和两侧细金属栏片。所有构件采用共用模型／碰撞数据，压顶可以承接从上方落下的玩家，栏片间的小空隙没有整块矩形空气墙。

`l11QuayRails.ts` 同时供区块生成与远景使用；类型由运河的步行属性决定，位置锚定世界坐标，宏区边界不重复产生石柱。普通种子也会生成此款栏杆。模型为项目原创参数化几何，复用已登记的 CC0 混凝土与金属 PBR 材质；没有新增噪点纹理或外部资产。

绿色桥梁侧面与上下边带共用 `l11BridgeSkin.ts`，沿实际缓拱分段，远景也包含朝下的桥底面。桥面厚度和两座桥墩沿用共用水系／碰撞数据。尺寸与支承截面仍是参考照片的合理推定，不能称为实测复原。

本轮静态检查：`check:l11-waterways`、`check:l11-collision`、`check:l11-meshes`。实机截图、上方落地、步行、普通种子和三次重载记录见 [canal-v13/runtime.json](reports/l11-reference/canal-v13/runtime.json)。此前 100 种原型的验收数字保留为历史记录。

## 店铺柱网与标牌位置（参考版本 14）

`l11RetailFacade.ts` 为 `pier-retail` 建筑提供连续立面分格及首层实体柱。开门后仍沿完整立面计算窗格，首层粗柱承接上层分格；柱体接入建筑细节、远景与旋转碰撞，适用于普通种子和四种入口朝向。柱宽、2.94m 高度及两窗格一柱是对照片的结构推定，原图未提供精确尺寸。

`l11ShopSigns.ts` 根据同一组实体柱选择能容纳完整横招的柱间区域，圆形挑牌的支架靠柱安装。既有完整标牌纹理、文字与宽高保持不变，没有新增图像资产。建筑细节不重复计入装饰原型数量，当前装饰仍为 103 种。

`check:l11-architecture` 覆盖四朝向、旋转实体、柱顶空间、实际门口、正反立面非整模数切分及招牌与柱体避让。实机入口、玻璃面外柱体碰撞和普通种子记录见 [storefront-v14-final](reports/l11-reference/storefront-v14-final/runtime.json)，正反与室内对照见 [本轮报告](reports/l11-reference/index-v14.html)。

## 绿化与树干连接（参考版本 15）

`plane_tree` 现包含 23 根带 taper 的 bark 圆柱、3 个实体 bark 连接球节点和 4 个非实体 `trimmed` 叶冠。树干保持灰浅色分叉形态，树冠使用修剪后的连续轮廓；`shrub_planter` 使用 2 个相交的非实体叶簇。建筑入口花坛和 ribbon-twins 水岸楼梯两侧均使用连续种植体，`l11QuayPlanting` 负责布置与装饰避让，普通种子共享同一规则。

建筑叶冠按完整尺寸传入几何生成器，叶冠下缘与种植面相交，近景细枝连接土面与叶冠。细枝和叶片均非实体，花坛挡墙及压顶保留实体碰撞。低质量档和远景沿用同一轮廓并降低密度。当前装饰原型仍为 103 种；v15 是既有原型的细化，不增加数量。

新增静态命令 `npm run check:l11-greenery`，验证 6 个树皮纹理文件的真实尺寸与哈希、16 组几何／UV／缓存条件及树干连接节点。实机检查、普通种子样本和仍待还原项目见 [v15 对照报告](reports/l11-reference/index-v15.html)。通过功能检查不代表视觉还原已完成。

叶冠源几何缓存限制为 96 项和 32 MiB，按最近使用顺序淘汰。合批器已复制顶点，源几何回收不会销毁在场模型；压力检查同时验证确定性重建及已合并模型保持有效。

## 店铺陈设与朝向（参考版本 16）

本版本登记了三种店铺陈设道具，均属于实体、无交互、非容器，正面为 `-Z`，`placement` 为 `shop`；当前 L11 共 108 种装饰原型：

| ID | 中文名称 | 尺寸（宽×深×高，m） |
| --- | --- | --- |
| `l11_retail_gondola` | 双面商品陈列架 | 1.2×0.92×1.48 |
| `l11_retail_checkout` | 店铺收银柜台 | 1.6×0.85×1.25 |
| `l11_retail_cooler` | 玻璃门饮料冷柜 | 1.2×0.72×2.05 |
| `l11_canal_ladder` | 运河登岸梯 | 0.8×0.45×3.5 |
| `l11_sewer_outlet` | 岸墙排水口 | 1.4×0.28×1.3 |

`l11RetailLayout` 按店门朝向生成收银台、双面货架、靠不透明墙的冷柜及灯具网格；渲染和碰撞使用同一部件描述，普通种子沿用同一套规则。商品品牌、价格以及参考照片中无法辨认的海报文字没有补写；本轮没有新增图片资产或噪点纹理，沿用现有已登记材质。

从室外看店铺时，真实光照档只启用实际有阴影的前两盏店内灯，并服从更低的用户阴影预算；经典档和关闭阴影时不增加这些店内点光，店内照明沿用原规则。`verifier/l11-retail.ts` 覆盖两个模式的 0/1/2/4 阴影设置。

`l11ReferenceDetails` 的连廊底面长条板缝、两端支承和收边在各距离层级共享同一结构描述。相关尺寸是基于单张照片推定，并非实测数据。

可运行检查命令为 `npm run check:l11-retail`；报告入口见 [L11 参考报告](reports/l11-reference/index.html)。完整验证结果与仍待还原项目见报告。

`l11Twins` 统一四个临街方向的塔楼、内侧蓝色立面、楼顶连接和下方入口。蓝色／深色中窗／蓝色的组合仅位于连廊下方，其余深处侧墙使用浅色玻璃；横向分格和红色细条采用两层一组的外观节奏，建筑实际楼层高度保持 3m。分格比例仍是对原图的推定。

`npm run check:l11-twins` 检查四朝向、三级模型共 12 组局部／旋转世界坐标的一致性、蓝色板块位置、连廊两端支承及上下表面碰撞。该检查不以照片相似度作为通过标准。
