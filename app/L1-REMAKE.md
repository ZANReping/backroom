# Level 1 重制：实现与复现

本轮只修改 Three.js 游戏 `app` 及根说明。五个现有区段、小径和据点外部入口采用新建筑；据点目的地、内部服务和玩法保留。联机继续关闭，本轮不更新协议或做联机验收；不涉及 `app-lite`。传说段不在本轮范围。

当前实现为 **L1 生成 v4 / 烘焙算法修订 6**。以下“第二至四轮”为历史记录；当前数据流、照明和验收限制以文末第五轮及 [第五轮报告](reports/l1-remake/iteration-5/REPORT.md) 为准。

## 空间与材质

- **天鹰段**：世界坐标梁柱与折墙替代区块四面围墙。方柱大厅、圆柱、狭长通道与小房间由独立空间参数选择；干湿、洁净度和照明分开。漏水由连续不规则足迹组成，地面湿度与可见水洼使用同一查询；真实光影使用单个 512²、15 Hz 的近邻反射目标。
- **跃金段**：普通模块 6.2 米高顶，展示配置独立标定；细柱、深色顶梁与波纹顶板、大风管、吊灯。内部墙体接到实际屋顶，板条箱集中于局部空间。
- **哥特段**：普通模块 6 米柱距、3.65 米拱顶，圆柱与连续交叉曲面；柱身在 1.35 米起拱处接入曲面，相邻曲面共用边界细分，避免重叠和 T 形接缝。展示参数保存在参考配置中。
- **衔尾段**：灰白混凝土及剥落粉刷、暗顶、红管、线槽、悬线和倚墙材料；保留施工人员及其交互。人员模型按实际雾距与视锥裁剪，24 米内预热，远处不继续渲染不可见角色。
- **花园段**：高柱、低矮地被、柱面叶簇与垂藤、真实顶板开口；采光来自固定世界方向的开口发射面，不再随玩家切换单盏日光。叶片采用 alpha test，高低档降低叶簇密度；采光和光柱在停电时一并消失。
- **小径**：不再是第六个宏观区段。以门后的短走廊和侧房嵌入五区，白刷砖墙、旧座椅、靠墙空调机和少量杂物。门沿用真实碰撞和交互；内部不直接生成停电追猎实体，外部实体仍可追入，无自动恢复属性。

布局沿用 32 米流式区块。大区连续分布，天鹰为主体；跃金、哥特较大，花园、衔尾较小且稀少。区段边界以高度、梁柱和实际隔墙过渡。`l1Spatial.ts` 为纯世界坐标查询；材质、灯位和碰撞在普通游玩与展示种子中共用实现。

## 单机机制

1. 平时原生灯稳定，闪烁事件先预警，再停电 45–90 秒；恢复后等待 300–600 秒。五区和小径的原生灯、花园采光均受影响。小径入口保留弱绿色应急标识，手电与投出光源保留。
2. 板条箱每 30 秒尝试一次低频变化，普通尝试最多改变一个；停电结束时变化更明显。12 米内、当前可见、最近 5 秒被看见、正在搜索、玩家存放物品及稳定设施附近的箱子受保护。空箱搜刮状态和内容持久保存，不因重新出现而补货。
3. 花园持续暴露约 300 秒致命，保留阶段提示、僵硬减速；离开后恢复，满暴露量约需 150 秒消退。
4. 区段连接处的距离系数连续变化于 0.72–1.35；小径维持正常距离。
5. 据点入口保留原目的地，新增工业门体、组织标识与沿途引导；首次进入 Level 1 不自动揭示全部据点。
6. 主存档与 `L1WorldSave.version` 仍为 1，生成版本为 4；旧档增加可选的幂等迁移记录。新版建筑先生成，再将冻结的旧随机序列产生的物资身份和交互投放到合法空间，不为物资挖掉柱墙。保留停电、花园阶段、搜刮内容、显隐和已拾取身份；只调整被新几何覆盖的位置。掉落在原区块内找不到安全点时抛出错误，不以删除物品或刷新补给掩盖失败。

## 资源与成本

优先复用许可明确的 CC0 混凝土、金属、粉刷砖墙、木材和叶片贴图。本轮没有生成新的 AI 纹理。详见 [作者及许可](L1-REMAKE-SOURCES.md) 与 [纹理文件记录](public/textures/l1/SOURCES.md)。模型、布局及 UV 为项目实现；参考照片不作为背景或游戏材质。

颜色/GL 法线共用已有加载与质量设置，粗糙度仅真实模式请求。静态建筑每区块按材质合批；灯具实例化；顶板和管线直接写入合批缓冲。叶片使用单层 alpha test，高低档控制密度。几何和私有材质独立回收，共享纹理不随单个实例销毁。

真实光影降低无方向补光、环境反射和白平衡偏黄；动态曝光对 Level 1 的增益上限为 1.35。黑暗区保留需要玩家光源的范围。经典模式共用新建筑和颜色贴图；没有新建全场后处理遍数或额外场景阴影灯池。

## 查看与复现

普通新开局可在设置输入十进制种子 `20261006`，随后进入 Level 1。正式游玩中的危险和交互仍存在。

独立验收页使用内存存储，不写玩家存档。在 `app` 启动：

```powershell
$env:L0_VERIFY='1'
npm run dev -- --host 127.0.0.1 --port 3004
```

打开 `/verifier/l0-remake.html?level=1`，用“参考视角”逐项选择 18 个取景点。`anchor=garden` 等参数可直达取景点。每个点的世界坐标、眼高偏移、朝向、FOV、原图画幅保存在 [cameras.json](reports/l1-remake/current/cameras.json)。截图按参考画幅生成，最长边不超过 1920；性能统一 1920×1080，固定画质与分辨率。

- “生成全部参考画幅”：在真实地图逐点渲染 PNG，结果位于页面展开项；不使用截图专用材质或平面照片。
- “功能回归”：实际引擎的停电、箱子变化/持久化、花园结算、小径门开关、据点入口和取景净空检查。
- “六区域性能验收”：新版五区及小径各预热后采样五轮，核对实际区段。每轮至少 120 帧和 1.2 秒，同时记录 RAF、CPU render 与 GPU 查询。
- “相同坐标性能对照”：保持改造前坐标与相机；**新地图在这些位置可能已是不同区段**，不能替代六区域验收。
- “检查切区与画质回收”：四轮跨区及经典/真实模式切换，回到同一地点记录资源。
- “开始自由游玩”：恢复正常碰撞和机制。固定取景默认冻结状态，不能用固定取景代替玩法验收。

前三轮浏览器工作使用 Codex 内置浏览器的隐藏页面。第四轮按最新要求改用独立 Chrome `--headless=new` 和直接 CDP 脚本；启动参数、GPU、视口、错误、截图均保存，脚本关闭自己创建的浏览器。两种浏览器的性能数据不能直接当作同环境前后对照，也不作为 Android 真机结论。

```powershell

npm run check:texture-images
```

最后一条命令只把已保存的截图与本地参考图生成并排图/半透明叠加图，不启动浏览器，也不产生建筑误差通过分数。[完整验收记录与未达标项](reports/l1-remake/REPORT.md)。

## 第二轮纹理与布局调整（2026-10-08）

普通种子的大厅采用世界坐标 64 米开放隔墙组合，以错位长廊、L 形隔墙、开放侧凹和旋转变化组织空间；与 32 米加载区块独立。外围留通路，保留出生、门口、出口、物资和交互净空。展示种子的侧墙仍是具有实际碰撞的同类建筑，参考相机参数保持不变。小径侧房增加连接支路，内侧墙面逐面使用粉刷材质，走廊保留白刷砖。

非花园地面复用现有 CC0 磨损混凝土，颜色、法线与粗糙度共用 UV。天鹰和小径顶面使用细粉刷纹理，修复顶面每一米重复重置的问题；墙面改用主轴投影。柱脚增加轻度不规则污损，降低梁体及管线的视觉重量。积水边缘加入不规则流痕和透明过渡，反射随视角变化，仍只使用一张 512 像素反射目标、最高 15Hz 更新。板条箱补齐封闭顶底、四面边框与顺向木纹。

验收页增加“普通种子与接缝取景”，生成种子 1、42、7391 的区块两侧画面。新一轮证据单独保存在 [iteration-2](reports/l1-remake/iteration-2/REPORT.md)，不覆盖前轮基线。离线对照脚本可传入 `iteration-2`：

## 第三轮顶面与服务几何（2026-10-08）

降低粉刷扫描的污渍对比和法线幅度，移除柱脚的重复竖纹；天鹰与小径细管贴近天花板。小径侧房采用平顶、靠右墙纵向灯管和沿墙管道，普通种子与展示种子使用相同房间规则，照明和停电同步；参考座椅、设备位置进一步校准。

逐米直管、梁、桥架与仓库顶板肋条先合并同轴连续段，再生成材质批次，保留墙体断口、接头和世界 UV。四类服务几何的面数减少 75.2%–85.9%；这是构件级结果，整场稳态帧率未显著变化。六区 1080p 五轮稳态均通过，冷构建仍有约 487ms 长帧，视觉构图未达到 3% 误差目标。[第三轮报告](reports/l1-remake/iteration-3/REPORT.md)记录完整前后截图、实际画布尺寸、测试和剩余差异。

验收页支持本机忽略目录快照 `?level=1&baseline=l1-iteration3`；基线不是生产依赖。离线脚本参数使用 `iteration-3`。前轮衔尾独立复测实际为 1280×720，已在原报告勘误，不能当作同设置 1080p 结果；第三轮六区同时保存 `viewport` 和 `renderSize`。

## 第四轮连续材质、构件与光照（2026-10-08）

地面、外墙和顶面采用共享的世界坐标材质场：颜色及区段权重写入一张 128×512 数据纹理，以 2 米采样、16 米范围平滑混合。大尺度连续噪声负责色差和磨损，地面不再按方格或区块抽取颜色；相邻区段共用地面扫描、世界 UV，花园土层和衔尾剥落法线按同一权重混合。小径砖墙及房间粉刷偏淡蓝冷色。数据场随加载窗口重定位，同一世界位置保持一致。

柱体按稳定世界哈希选择局部补漆、低护角、附墙细管、金属夹具、裸混凝土及剥落面；哥特柱保留连续拱顶衔接，花园保留爬藤。天鹰局部与衔尾顶面加入成束红线和白管，沿用连续段合并、材质合批。板条箱改为约 0.99×0.71×0.68 米的长方体，碰撞深度同步，正反面有稳定数字及朝上标识。

L1 原生灯沿用 Level 0 的原生/便携光源区分，增加向下发光响应、近地间接光衰减和附近灯软阴影。两盏场景灯保留，按质量档 200/100/50ms 更新；周期更新错开，几何/光源变化立即失效，手电独立刷新。花园使用最多四束柔边透光体（一个实例绘制批次），依原生灯和停电状态更新；低质量及经典模式关闭。它是低成本体积光近似，不是全屏光线步进或完整体积阴影。

预警期间人眼曝光保持不追逐闪烁；停电后暗适应时间常数 3.6 秒，最大增益 1.35；复电亮适应约 0.25 秒并短暂柔化亮部。箱子异常变化现在只切换自己的模型可见性并更新碰撞，不再递增全层渲染重建号；资源及物资身份保留。

## 第五轮：统一建筑与静态照明（2026-10-08）

`world/l1Building.ts` 输出不可变的 `L1ArchitectureData`：楼板、柱墙、开口、顶面、梁管、灯具与积水。碰撞、地图、灯具、Worker 几何和遮挡积分共同读取它。`l1ReferenceCases.ts` 提供十八组建筑参数、相机与人工标注关键点；普通种子共用参数化模块。旧生成器暂时保留为物资身份/随机序列清单，结果由 `l1Placement.ts` 投放到合法空间；它不再决定新版建筑，仍有重复生成 CPU 成本待消除。

`world/l1Bake.ts` 是离线与 Worker 共用的纯 CPU 积分器。每个目标区块读取确定性的 3×3 建筑邻域，BVH 查询墙柱、顶面与地面的遮挡；竖灯使用自身安装位置、方向和发光尺寸。高档每光源两次面积采样、两次低分辨率漫反射传递，低档一次采样/一次传递。间接路径每段限 6 米，间接缓存步长 1.8 米；它是有预算的近似，不是路径追踪或完整 GI。哥特遮挡曲面为 1 米三角网，显示网格更密，因此极近距离阴影仍可能有误差。

输出为高档 512² / 低档 256² 的线性 HalfFloat 照度图、方向图、独立 UV1、分材质几何及 4 米间距探针。光照图留一像素边缘扩展、不生成 mipmap；基础 PBR 贴图继续使用原 mipmap 与世界尺度 UV。静态建筑屏蔽已经烘焙的原生点光贡献；动态物件使用间接探针加有限实时点光，手电与荧光棒继续实时照明。原生供电权重同时控制烘焙图、探针、灯管与花园光柱，应急标识独立保留。曝光计量读取当前已安装探针并乘供电权重。

花园天窗使用固定世界方向，最多 16 束透光实例共用一个批次；按开口及 12 个遮挡采样检查整束是否可见。这不是逐像素体积阴影，叶片也未烘焙进静态 atlas。花园叶簇在高/低档间降低密度，尚未恢复按观察距离的三档模型 LOD。

后台重任务桌面最多两个、移动端一个；内存缓存上限 96 MiB / 80 项，IndexedDB 128 MiB，版本、质量和建筑内容指纹共同识别结果。过期排队任务取消、运行中的旧结果不安装。共享缓存结果有引用计数，几何和材质实例独立释放。主线程调度每轮 2ms，但一次模型创建、纹理上传或编译提交仍不可抢占，**不能将该预算视为已经消除长帧**；分阶段 CPU 耗时与异步等待分开记录。

IndexedDB 的独立 `usage` 表仅保存容量和访问时间，不在回收时读取整批几何数组；存储结构升级只清理可重算的烘焙缓存，不触碰存档。离线文件 gzip/JSON/base64 解码也使用原 Worker 池，同时兼容浏览器已按 HTTP Content-Encoding 自动解压的 JSON。`decodeMs`、`offlineLoads`、`diskHits`、`computations` 分开记录，内存请求复用的 `hits` 不作为磁盘命中率。

展示种子十八个中心及其相邻区块共 162 块高档离线光照保存在 `public/assets/l1-bakes`，只按需请求。低档及普通种子使用相同算法后台计算。生成命令如下，运行目录为 `app`：

```powershell
node node_modules/esbuild/bin/esbuild scripts/export-l1-v4-references.ts --bundle --platform=node --format=esm --outfile=.cache/export-l1-v4-references.mjs
node .cache/export-l1-v4-references.mjs
$ids=((Get-Content reports/l1-remake/iteration-5/reference-data.json -Raw | ConvertFrom-Json).cases.psobject.Properties.Name) -join ','
npm run prebake:l1 -- --anchors $ids --radius 1 --out iteration-5/offline --publish
npm run check:l1-bake -- --high
```

性能测量不要和预烘焙、生产构建或其它 QA 浏览器并行。`L1_QA_ANCHORS` 可逗号分隔筛选参考点；`reference` 阶段只生成所选参考视角。验收页 L1 的 120 秒等待是失败看门狗，不是性能通过标准。关键点投影、局部线性亮度和人工观察分开记录；关键点未全部进入 3% 范围，不能宣称照片级精确复刻。完整结果及未完成项见 [第五轮报告](reports/l1-remake/iteration-5/REPORT.md)。

## 第六轮：相机、门洞透光与构建尖峰（2026-10-08）

按源图画幅联合调整相机位置、眼高、偏航、俯仰和 FOV。`scripts/fit-l1-cameras.ts` 只输出建议，不自动接受；`safe` 检查建筑及物资碰撞下的落点净空，不能代替画面遮挡检查。相机元组为相对中心的 X/Z（米）、眼高偏移（基准 1.55 米）、yaw/pitch（弧度）及垂直 FOV（度），画幅取源图比例。两个点不足以唯一确定相机，多数场景仍需更多人工标注。哥特圆柱起拱边缘使用实际 24 边柱体的可见轮廓计算，不把柱体世界 X 极值误当屏幕边缘。天鹰小房间与阴暗场景增加柱顶标记，调整真实隔墙、柱位和顶高后再取景。源图中已有标记坐标没有为了降低误差而移动。

构件增加圆形红线/白管截面、开放式线槽、跃金次梁与哥特停车线；圆柱补漆包覆圆截面。白管参与遮挡，普通灯的少量向上出光照亮梁顶。阴暗天鹰采用有遮挡的服务区集中照明，仍保留未亮灯具。竖灯的安装侧可由建筑模块指定，模型和烘焙共用位置及方向。

烘焙算法修订为 **r7**，生成版本保持 4、存档版本保持 1。每块最多记录八个邻近真实门洞的原生光路径贡献，保存为两层 RGBA 遮罩；门扇开度驱动透光权重，静态表面及动态物件探针同步变化，便携光源不乘此遮罩。门洞上方过梁参与固定遮挡，门的稳定 ID 随既有开关记录恢复。它是路径贡献近似：多扇关闭门的重叠贡献可能过度变暗，不能替代连续旋转门扇的逐像素间接阴影；不增加场景灯数量，也不重烘焙整层。

CPU 采样确认了 HDR 首次绘制时的程序查询阻塞，以及跨区水面反射重复构造湿区。L1 现在对实际 composer HDR 目标预编译/预上传，提交后恢复原目标；把自定义方向/门洞纹理也纳入预上传。湿区几何逐行让帧，反射复用已安装区块的水洼顶点及同一个反射目标；旧物资清单不再重复计算随后被覆盖的湿区。其它层级沿用原目标选择。2ms 调度仍不能抢占单次模型创建或 GPU 调用，长帧需继续单独报告。

`L1_QA_ANCHORS` 同时支持选择相机拟合、参考截图和稳态性能场景。局部重烘焙可用 `prebake:l1 -- --anchors ... --radius 1 --publish --merge`，验证种子/质量/半径一致后保留未修改的发布条目。发布目录应始终保持完整 162 项；只重算相机不需要重烘焙，建筑变化必须更新受影响邻域。

## 第七轮：参考角度、仓库及侧房（2026-10-09）

相机元组扩展为 `[dx,dz,eyeOffset,yaw,pitch,fov,roll?]`，滚转默认 0；角度单位仍为弧度，仅 FOV 使用度。拟合脚本加入小幅滚转并识别共线标记，输出建议后仍需真实截图复核。`final/actual-cameras.json` 保存截图瞬间的相机矩阵与画幅，比较脚本优先用它投影关键点；冻结截图时使用中性呼吸相位，避免加载时间影响眼高。源图没有被扭曲成游戏画面。仓库的低机位、哥特的较高机位是明确的摄影点，不改变正常玩家的默认眼高。

跃金新增工字柱、纵向深梁、横向次梁、双圆风管与管箍，矩形灯安装在深梁下方。新增 [ambientCG CorrugatedSteel009 的 CC0 原始文件与许可记录](assets/sources/CorrugatedSteel009/SOURCE.md)，执行 `node scripts/prepare-l1-steel.mjs` 可重新生成 512² 颜色、OpenGL 法线及粗糙度版本。

`l1Dressing.ts` 在建筑完成后生成小径房间陈设；`l1Placement.ts` 保持物资身份并避开有陈设的房间及入口。窄侧房与凹间是同一套建筑/碰撞/烘焙数据，白刷墙不再按完整旧墙面中心误判。外机与油漆桶每实例拥有几何和材质，纹理可共享。

`l1VaultMesh.ts` 裁切柱口时插入共用边界分段，中心扇形保留高度变化，修复二维面积正确但三维有缝的情况；`l1VaultMaterial.ts` 为柱身与拱根提供颜色/法线/粗糙度的世界三向投影，独立照明 UV 不变。新网格版本计入哥特内容指纹，烘焙修订 r10；发布清单含 18 视角共 162 块，旧修订在请求离线文件前即被拒绝。
