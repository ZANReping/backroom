# 各层级稳态性能评估（2026-11-07）

这次只改了玩家已经在层级里时每帧都会走到的 CPU 路径：小地图/探索视线、交互目标扫描，以及 Level 601 在渲染器建完场景之前的结构碰撞查询。没有改网格、材质、光照、批次或存档格式，因此不能从这次数据推断绘制调用数或画面帧率。

## 测了什么

可玩层级以 `levelDefOf` 为准，而不只是 `LEVELS` 数组：

| 组 | id | 生成 |
| --- | --- | --- |
| 主线 | 0–11、12（显示为 Level 601） | 0–11 无限区块；601 有限图书馆 |
| 子层 | 902 Level 0.2 | 无限，复用 Level 0 管线 |
| 序章 | 900 前厅 | 有限据点图 |
| 酒店口袋 | 117 办公室、118 大堂、119 Level 5.1 赌场 | 有限据点图 |
| 据点 | 101–110、116、274 | 有限手工图。Level 5 的其它楼层共用 `infiniteL5`，本次只测了默认到达的 1F |

玩家在这些层级里共用同一套运行时：

- `Engine.update` → 移动、生存、实体 AI、交互扫描、8 米探索圆、`mapSight` 视锥
- 无限层 `updateInfiniteWindow`：跨区块时主线程拼接；浏览器里另有 `chunks.worker` 预生成
- `structGrid`：无限层和据点在场景上传时建空间索引；Level 601 原先要等到 `buildLevel` 末尾
- 渲染器的区块流、静态合批、光照不在本次测量里。`app/verifier/performance.html` 仍是绘制调用和浏览器帧时间的现成入口

## 方法

Node 里直接跑真实 `Engine.loadLevel` / `Engine.update`，不经过 WebGL。种子 `424242`，`firstVisit: false`，无敌且锁定属性。稳态样本在渲染器同款的 `enableRuntimeStructCollisionIndex` 之后采集。视线样本每步平移 0.25 米并转 0.02 弧度，用来绕过「原地不动才命中」的结果缓存。

这不是 GPU 帧时间，也不是帧率。60 Hz 预算只作为读数的参照（约 16.7 ms），不能据此说游戏达到了多少 FPS。

环境：Node v22.23.4，x64，4 核 Intel Xeon（2026 云主机），单线程。原始行在 `baseline.json` 与 `after.json`。

```bash
cd app
npm run profile:level-runtime
npm run check:level-sight-cache
```

`profile:level-runtime` 不带参数会覆盖 `reports/level-runtime-performance/profile.json`。对照时请先把结果另存。

## 基线里真正贵的部分

走动 120 帧的 `Engine.update` 中位耗时，和单独的视线/交互采样对得上：贵的是「玩家一动就整表重建」的查询，不是实体 AI（除 Level 8 约 35 只实体、中位更新 2.5 ms 里 AI 占了一截）。

- Level 0 / 1 / 4 / 9 / 10 / 0.2：每帧 `mapSight` 都对窗口里的全部实心结构调用 `structColliders` 并新建格子表。Level 0 连续 80 次这样的查询堆了约 50 MB。
- Alpha 基地：6921 个结构。小地图视线中位 2.84 ms；交互扫描中位约 1.2 ms（p90），因为 `scanInteract` 每帧量完全部结构。该层 `fullMap`，8 米探索圆直接跳过。
- Level 11：视线索引本来就会复用，单独的视线中位只有 0.72 ms。走动中位 1.05 ms。
- Level 601：索引还没建时，一次 8 米视野刷新的 p90 是 **197 ms**（12 次样本）。索引建好后同一函数降到约 1.3 ms。游戏主循环在场景就绪前会暂停模拟，所以这 197 ms 不会每帧打在操作上，但加载期间的视线/碰撞查询会扫完整座图书馆。
- 进入层级的 `loadLevel`（含生成，不含存档写入）：Level 11 约 0.62–0.74 s，Level 1 约 0.49 s，Level 7 约 0.42 s，Level 8 约 0.30 s。这是生成成本，不是稳态帧。
- 无 Worker 时跨一个区块：Level 1 约 90 ms，Level 7 约 85 ms，Level 8 约 60–70 ms。Node 里 `chunks.worker.ts` 起不来，这段包含了主线程生成。浏览器里已有预生成，**不能把这个数字当成玩家机器上的卡顿**。

绘制调用、三角形、GPU 时间这次没有重测。改动不碰场景图。

## 改动

1. `mapSight` 的结构格子表对所有层级复用，直到区块版本、碰撞占地版本、楼层或眼睛高度越过障碍物的垂直边界。非 Level 11 仍按玩家 ± 射程丢掉格子外的碰撞体，射线结果与逐帧重建一致。Level 11 不走这道射程剔除。原地结果缓存的阈值没有放宽。
2. Level 0 / 0.2 的 8 米分区墙列表按区块版本保留，每帧只按眼睛高度和 8 米范围过滤，不再 `flatMap` 出新数组。
3. `scanInteract` 用 8 米足迹格子取出附近结构，再用原来的 2.2 米表面距离丢掉其余的，并按原数组顺序排回，避免同分时换目标。
4. 有限且非据点的地图（Level 601）在 `generateLevel` 返回前就建立结构碰撞索引。据点本来就会在场景上传的第一行建立，没有再做一次。

存档字段、层级外观、实体数值和合批都没有动。缓存都在 `WeakMap` 里，不进存档。

## 回归

`npx tsc -b --pretty false` 通过。`NODE_OPTIONS=--max-old-space-size=8192 npx vite build` 通过（2665 个模块）。默认 Node 堆在这台 16 GB 机器上打到约 2 GB 后 OOM，加大堆后 59 秒完成；字体运行时解析警告和既有的大包提示还在，与这次改动无关。

`npm run check:level-sight-cache`：

- Level 0、1、4、601：复用的视线索引与 `mapSight(..., true)` 全量重建的格子和命中点一致；5 cm 位移会重算视锥；跨区块后仍然一致；玩家回到同一点时 8 米可见格不变。
- 同上三层加 Alpha：16 个站位上，格子交互目标和暴力扫描整个结构数组的目标一致（kind、文案、结构/物品/出口/NPC 引用）。
- Level 601 视野刷新 p90 为 0.84 ms，低于 25 ms 的回归线（无索引时约 15 ms/次，p90 197 ms）。

## 还没覆盖、也不要当成已经变快的部分

- 没有在 Chrome 里重跑 `verifier/performance.html`。绘制调用、三角形、合成器、阴影和真机帧时间都没有新数字。需要的话用现有 `scripts/run-performance-cdp.mjs`，并确认不是 SwiftShader。
- 区块跨窗的 60–90 ms 是 Node 主线程生成。浏览器 Worker 路径没有在这次重测。
- Level 6 的 8 米逐格 LOS、Level 8 的实体 AI、Level 1/7/11 的地图生成时间都还在。改它们会碰到探索结果、追击时序或地形，这次没有动。
- Level 5 只测了默认 1F。2F–12F / B1 走同一个无限酒店生成器。
- 单次采样。亚毫秒的上下浮动（例如 Level 1 索引前视野 0.78 → 1.05 ms）不要读成退步。
