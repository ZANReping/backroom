# Level 1 第六轮：参考相机、门洞透光与流式构建

本轮联合调整了参考相机与部分实际建筑，补充了门洞对原生烘焙光的动态遮挡，并修复 HDR 预热及水面反射的重复构建开销。**整体视觉仍未达到参考图轮廓 3% 的验收目标。** 关键点投影、画面观察、功能与性能分别记录，不能互相替代。

范围为 `app` 及项目说明，保留已有工作区内容。据点内部沿用原版，联机继续冻结。没有引入新外部模型或生成纹理，沿用 [已有资产许可](../../../L1-REMAKE-SOURCES.md)。

## 相机与建筑

相机标定使用原图画幅，同时调整位置、眼高、偏航、俯仰和 FOV；不对游戏截图做透视扭曲、自动配准或颜色匹配。优化脚本只提出候选，实际游戏负责验证落点净空。衔尾段首次候选与箱子碰撞，已修正相机并把物资碰撞加入筛选；[原失败记录](attempts/runtime-camera-clearance.json)保留。

- 十六个参考视角更新了取景参数。小径房间与板条箱暂保留原取景：两者的房间/物件配置尚不匹配，单改相机不能解决。
- 小房间增加真实 L 形隔墙及后部开口，调整柱网与竖灯安装侧；阴暗天鹰调整顶高、柱旁墙距和集中照明位置。普通种子与展示场景共用建筑、碰撞及烘焙实现。
- 哥特柱缘按实际 24 边截面的屏幕轮廓计算，避免把世界坐标 X 极值误认为画面左右边缘。天鹰小房间和阴暗场景各新增一个柱顶标记，原有源图标记没有为了降低误差而移动。
- 红色细线、白色管道使用圆截面，线槽改为开放梯架；增加跃金次梁及哥特停车线，圆柱补漆保持圆形包覆。

当前 40 个标注点中 35 个在横纵各 3% 内，三个点的小房间最大误差约 1.56%，阴暗天鹰约 1.13%；哥特仍约 3.51%。这些只是选定点的投影误差：多数场景仅有两点，无法唯一约束相机，也未包含全部可见柱缘、梁线、灯具和陈设。不能据此宣称整幅照片复刻通过。

## 光照与构建

烘焙修订为 r7，生成版本保持 4，存档版本保持 1。每个区块最多记录八个邻近真实门洞的原生光路径贡献；动态门扇开度同步控制表面受光和物件探针。关闭门后原生透光减弱，开门恢复；手电、荧光棒独立计算。门洞过梁参与固定遮挡，门的稳定身份随已有开关状态恢复。

[门洞运行检查](final/portals.json)共七项通过。相同地面位置的像素亮度由关门时 2.52 增至开门时 14.89，再次关闭为 2.54；停电为 0，手电照亮为 166.01。它们是固定画面像素亮度，并非照度单位。开关门期间已安装区块对象不变。[闭门](final/portals/closed.png) / [开门](final/portals/open.png) / [复原](final/portals/restored.png)。

这仍是有预算的路径贡献近似：多个关闭门覆盖同一条路径时可能过度变暗；不等于连续旋转门扇的逐像素间接阴影，也不新增实时 GI 或额外场景灯。

L1 预编译和零范围上传使用实际 composer HDR 目标，提交后立即恢复原目标；自定义方向、门洞纹理也提前上传。湿区几何逐行让帧，反射复用已安装的水洼顶点及同一个反射目标。保留物资身份的旧生成清单不再重复计算随后被替换的湿区。

CPU 诊断采样发现首次 HDR 程序查询和反射几何重算是阻塞来源。带采样器的移动诊断最大 RAF 从 1,237.4ms 到 285.9ms，最大长任务从约 4,955ms 到 696ms；程序查询累计从约 11,959ms 到 1,005ms。但两次缓存热度不同，采样器本身有开销，**这些数字只用于定位，不作为受控性能提升百分比**。原始数据在 [baseline](baseline) 与 [after-streaming](after-streaming)。正式五轮结果另见 [PERFORMANCE.md](PERFORMANCE.md)。

## 性能与验收状态

RTX 4060 Laptop、Chrome 154、1920×1080、固定真实模式、动态分辨率关闭。六区预热后各五轮，稳态中位数 4.2–12.5ms。跃金、哥特、衔尾、花园的五轮 P95 均通过 20ms 目标；天鹰普通最差轮为 20.9ms，小径有一轮 38.2ms，**整体性能未通过**。小径该轮 RAF 最大 1,089ms，而 CPU render P95 为 9.3ms、GPU P95 为 11.23ms，现有日志不足以把异常归因于某个渲染函数，不丢弃该轮。

跨区构建最大 RAF 为 2,139.8ms。移动验证请求 128 米、按实际碰撞选步，历时 34.14 秒；中位数 9.7ms、P95 28.8ms、最大 506.2ms。它不是人工键鼠完整游玩，也不是稳定相机场景的性能。阶段日志中的异步等待不能与主线程阻塞相加。

四轮花园→跃金→哥特→天鹰→经典→真实切换后，资源始终为 **343 个几何、118 张纹理、95 个程序、7 个门洞绑定、0 个当前门状态**，本次路径未观察到持续增长。[原始资源记录](final/resources.json)。

首次移动脚本的 150 秒 CDP 总超时覆盖了两次预热和整段移动，先于整体检查结束；该失败保存在 [attempts](attempts/movement-cdp-total-timeout.json)。仅将该调用的总等待上限设为 360 秒，单次预热的 120 秒看门狗和帧时间阈值未变。重新验证完成，超时并未作为通过样本。

## 复现

完整实现与命令见 [L1-REMAKE.md](../../../L1-REMAKE.md)。本轮使用专属 Vite 3013、Chrome CDP 9264 和 `.cache/l1-qa-chrome-9264`，实际启动参数含 `--headless=new`，未连接日常浏览器或使用内置浏览器。

```powershell
# 工作目录 app；另一个终端先开启 L0_VERIFY=1 的 Vite 3013
$env:L1_QA_URL='http://127.0.0.1:3013'
$env:L1_QA_CDP='9264'
$env:L1_QA_REPORT='iteration-6/final'
$env:L1_QA_ITERATION='iteration-6'
foreach ($stage in @('v4','portals','runtime','cache','cross-level','capture','power','performance','movement','resources')) {
  node scripts/verify-l1-detail-runtime.mjs $stage
  if ($LASTEXITCODE -ne 0) { throw "QA failed: $stage" }
}
node scripts/compare-l1-v4.mjs
node scripts/summarize-l1-v4.mjs
npm run build
```

发布的 162 个高档离线条目均为 r7；局部重算通过 `--merge` 保留其它参考区域。压缩文件总计 109,648,979 字节，按需加载，未要求启动时下载全部。相机纯调整不改变烘焙；真实墙柱变化后重新计算了受影响的十八个邻域条目。

`result-*.json` 的通过表示脚本断言与运行错误检查通过；视觉及性能指标以各自报告为准。保留失败及诊断记录，不用后续成功覆盖原有失败事实。

全部最终无头阶段的游戏运行时与控制台错误计数为 0。验证脚本关闭了自己的 Chrome；验收结束另行核对命令行及 PID 后关闭本任务 Vite 3013，保留用户及其它任务的进程。
