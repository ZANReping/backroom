# Level 1 v4 建筑与静态照明重构

本轮已接入统一建筑数据、静态遮挡照明、后台计算、离线资源和旧档迁移；**整体视觉验收尚未达到参考图 3% 目标，加载及持续移动也仍有长帧**。本报告区分已经实现的机制、实际验证结果与尚未完成的验收项。

范围仅 `app` 及项目说明，据点内部保留原实现，联机保持冻结。原有其它改动不回退。无新外部模型或 AI 纹理，来源继续见 [许可记录](../../../L1-REMAKE-SOURCES.md)。

## 实现

- `L1ArchitectureData` 定义墙柱、顶面、梁管、开口、发射面与材质归属；生成、碰撞、地图和烘焙共用数据。32 米区块是加载单位，柱网与建筑端点使用世界坐标。
- 五区及小径采用参数化模块；十八个 `L1ReferenceCase` 包含参考画幅、相机、模块参数、关键点及亮暗采样区域。物资最后投放，不再为了原物资位置拆柱挖墙；保留原随机清单以保持物品身份。
- 原生静态受光包括面积发射面遮挡和高档两次漫反射传递；独立 UV1、HalfFloat 照度、方向图、间接探针与便携实时照明分开。相邻建筑在未加载时同样参与积分。
- 展示种子 20261006 的十八个中心及邻区共 162 个高档离线结果按需加载；普通种子共用算法与 Worker。桌面最多两项后台重任务、移动端一项；内存和磁盘缓存有界，内容指纹和算法修订检查过期结果。
- 缓存回收改读小型容量索引，避免每个区块到达时克隆已有全部大数组；离线 gzip/JSON/base64 解码也放入同一 Worker 池。原先缓存开销下取得的完整性能和移动数据保存在 [before-cache-fix](before-cache-fix)。
- L1 生成版本 4，主存档及 L1WorldSave.version 保持 1。增加幂等迁移记录；保留搜刮、物品身份、背包、属性和事件，只移动被新几何覆盖的位置。掉落找不到安全点时抛出错误，不删除物品或刷新补给。

## 视觉观察与未达标项

| 场景组 | 已改善 | 仍存在的差异 |
|---|---|---|
| 普通天鹰 | 柱网单独标定，柱旁竖灯有真实侧向发射面；遮挡与探针独立于玩家位置 | 顶面偏亮，管线数量/截面、湿区轮廓和反射仍不同；三个标记点符合目标不代表全部轮廓通过 |
| 圆柱、房间、明亮、干净、干燥天鹰 | 不同柱距/柱宽/顶高和涂层，连续材料变化 | 多数消失点与开口位置仍有偏差，梁管没有逐张精确排布，干净场景白墙受光偏亮 |
| 阴暗与黑暗天鹰 | 少量灯和建筑遮挡形成深暗，未用曝光把全场抬亮 | 亮区位置、长阴影方向和顶管仍偏离原图；阴暗参考的远端亮口不足 |
| 装饰物天鹰 | 既有桌椅陈设、侧向灯和墙后遮挡保留 | 镜头及桌椅相对墙的位置不同，主灯位置需要继续标定 |
| 跃金 | 独立高顶柱网、接顶墙、吊灯与开放空间 | 顶梁/波纹板过暗，细部密度、白墙和灯位偏差明显 |
| 哥特 | 真实圆柱及连续曲面；修复柱顶重叠和相邻曲面 T 形裂缝 | 起拱比例、柱网透视、停车线及表面色差仍未完全符合；烘焙阴影的曲面网格比显示网格粗 |
| 衔尾 | 粗糙墙地、补漆/剥落、红色管束和施工陈设 | 管线、脚手架和墙柱污损分布未逐图对应，施工灯方向仍不同 |
| 花园 | 真天窗、固定采光方向、受遮挡约束的光柱和更细的叶簇 | 叶片仍明显重复，地被疏密和日光色调不同；缺少按距离的三级 LOD，仅有高低质量密度档 |
| 小径走廊/房间 | 实际门洞、冷色砖/粉刷，侧房灯与座椅 | 走廊开口、房间墙皮、相机与座椅构图仍有偏差 |
| 箱子/停电 | 稳定物品身份、可搜刮带编号长方体，原生照明同步停电 | 箱子参考为两只叠放，本轮仍是单箱；停电参考远端残光及柱位尚未匹配 |

## 近似与待完成工作

1. 38 个人工标注点不足以代表整张照片；尚需逐图补齐梁线、灯位和开口，继续按真实建筑参数校准，不能用后处理掩盖几何差异。
2. 漫反射只用 4/2 个方向、1.8 米间接缓存、每段 6 米路径；阴影细节与间接光平滑度仍有预算限制。探针只有一层高度，不能代替动态物件的完整方向性光场。
3. 门扇状态未参与不可变离线数据；当前开门/关门有实际碰撞和实时手电阴影，**原生烘焙的门洞透光还没有完成局部动态补偿**，关闭门后透光可能不准确。
4. 区块逐个准备完几何/材质/着色器后安装，当前没有相邻多块的统一提交屏障；中心初次加载有等待界面，长距离快速移动仍可能看见构建滞后。缓存修复不等于实现了无尖峰上传。
5. 旧生成器仍计算物资随机清单，主线程还承担部分已有道具模型与上传；单次同步操作不能被 2ms 调度抢占。阶段日志区分 CPU 提交和异步等待，不能把编译总等待当作同等时长的主线程卡顿。
6. 旧档迁移在实际游戏中验证了合法落点、柱体覆盖、幂等性与搜刮；未覆盖所有损坏存档、所有种子和全部出口组合。没有自动删除原存档。

记录到的回归包括：693 个展示/普通种子区块投放；烘焙有限数值、UV1、确定性、高低档和共享结果释放；负坐标接缝 17 个同位置采样最大线性差 0.00003052；18 个 L0 模型/模式构建；96 项贴图生命周期、66 项模型预热、11,621 项合批检查。生产构建通过，仍输出既有字体 URL、Browserslist 数据和大 bundle 警告。首次沙箱构建因 Windows realpath EPERM 失败，在本机运行同一命令后通过。

本机 Three.js 还记录了既有 `PCFSoftShadowMap` 弃用警告，实际自动回退为 `PCFShadowMap`；本轮未改动全层级阴影 API。最终性能脚本没有运行时/控制台错误或失败网络请求。

保留早期校准超时和脚本错误记录：旧 60 秒预热在哥特失败，之后调整为 120 秒看门狗；v4 检查曾遗漏材质数组处理，性能脚本曾遗漏 async 包装，均修复后重跑。`result-*.json` 中 passed 表示该脚本完成且无运行时错误，**性能和视觉是否达标必须看独立阈值报告**。

缓存改动前的资源检查与修复 HTTP 解码前的第二次移动检查由本任务主动终止，以避免混入热更新后的数据；已确认专属端口和启动参数后关闭对应 QA 浏览器/进程。它们不计为通过样本。最终性能采样串行执行，预烘焙、构建和其它 QA 浏览器未同时运行；末次生产构建在帧时间采样结束后的资源计数阶段完成。

最终缓存复检：JSON/gzip 两条路径分别在 Worker 内约 29.2/40.7ms 解码，数组完全一致；53 个缓存条目共 133,033,400 字节，低于 128 MiB，容量索引与实际键集合一致。验证完成后已关闭本任务专属 9260–9263 QA 浏览器以及 3011/3012 开发服务器，未操作用户日常浏览器。
