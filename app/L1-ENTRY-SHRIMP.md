# L1 进入速度与活旱虾手持预热

2026-10-20。修改 `app`，保留已有模型、物品行为、地图规则和存档。

L1 的主要等待发生在高精度静态受光，并非布局生成。现在缺少有效离线／磁盘烘焙的区块先计算有遮挡的直接受光，使用**最终建筑、碰撞、图集布局和 UV**显示场景；精细半影与两次间接受光在后台补齐。已保存的完整烘焙仍直接使用。

- 初始建筑优先于精细化任务；同类任务按玩家距离排序。桌面最多四个烘焙 Worker，后台精细化最多占两个，移动端仍使用单 Worker。
- 同时准备整个活动窗口，附近建筑和首次 GPU 提交完成后才解除进入等待。显示基础受光后仍继续生成远处区块。
- 精细化只更新光照纹理，每帧最多上传一张，约 0.45 秒混合过渡；不替换建筑几何、碰撞或物品。
- 临时结果不写入 IndexedDB，也不接受为有效离线资源。最终算法与第 17 版离线图集保持一致，生成版本及烘焙修订不变。
- 过期响应不能覆盖同键的新请求；离开活动窗口的待办任务被丢弃。跨层离开 L1 时直接停止后台 Worker，保留已完成缓存，避免继续占用其它层级的 CPU。

活旱虾的首次手持原先同时触发静态建模、手指接触求解、纹理上传及着色器首次使用。现在这些工作在加载画面期间分步完成，保留同一个手持实例和已求解的手指几何，并按当前光影、环境和袖长准备 GPU 资源。后续拾取与快捷栏切换直接复用。

三种旱虾物品共用有限的模板缓存，实例几何与材质仍独立持有，纹理共享。准备取消、同步工厂与后台准备竞争时释放临时资源；手持缓存仍最多 12 件，手部几何缓存仍最多 16 种。捕捉、放生、食用与交易规则不变。

测试数据、截图、命令与限制见 [验收记录](reports/l1-entry-shrimp/README.md)。
