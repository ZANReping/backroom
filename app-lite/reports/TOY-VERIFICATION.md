# Toy 功能验证记录 · 2026-09-26

结论：本地游戏流程、官方类型契约、真实 SDK 的 Web 降级行为、模拟客户端成功/失败流程通过。尚未验证真实 B站 App 分享面板、系统相册、原生横屏及平台生成二维码的扫码落地。

## 验证范围与证据

| 功能 | 已确认 | 仍需平台验证 |

## 真实 SDK 实测

从官方 HTTPS 地址下载 SDK 后，用原始脚本字节在独立 Chromium 页面运行，没有替换 `window.toy`。该脚本只保存在开发缓存，不进入发布 ZIP。

- 官方脚本：https://s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js
- 本次 SHA256：`4dd522d27330e440cb336463265585ce18448ebc00f616b57fa21602b67b7115`
- 普通 Web：`share=false`、`saveImageToAlbum=false`、`setContainerMode=false`、`getQrCode=true`。
- 本地页面没有平台父容器；二维码调用最终返回 `type=timeout`、`[ToySDK] handshake with parent timed out`。游戏使用自己的 8 秒超时释放界面，不无限等待 SDK。
- 5,242,881 字符的相册 base64 参数被真实 SDK 以 `invalid_param` 拒绝。游戏报告与二维码保持在 2,000,000 字符以内。
- 能力支持不等于当前页面具有有效 Toy 上下文，不能以 `isSupport('getQrCode')` 为真直接宣称二维码成功。

## 实施改动

官方 `toy.d.ts` 纳入 TypeScript 检查。分享目标发生变化时重新隔离组件状态；二维码 API 返回的平台 URL 用于复制。报告二维码和按钮请求按目标合并，失败移除缓存以便重试。操作超时、权限拒绝、参数拒绝和限流均给出可恢复反馈，不自动反复请求。新增首页跨设备入口只分享首页，不承诺迁移存档。

原版 `app` 的 src/scripts/public 哈希核对无变化。发布目录与 ZIP 都通过严格的 50,000,000 字节检查，精确数值见 `package.json`。

## 上传后验收

1. 在 B站 App 打开已发布 Toy，竖屏点击“横屏沉浸游玩”；检查实际旋转、系统栏、安全区和退出全屏。
2. 生成生存报告，尝试允许/拒绝相册权限；确认允许后实际写入图片，拒绝后仍可下载或复制链接。
3. 分享首页和报告，用另一台设备打开；确认报告数据一致且本地存档不被覆盖。
4. 房主创建房间后展示二维码，另一台设备扫码、主动加入；检查双方开始游戏及房主离线提示。

只有完成这些平台验收，才能把原生操作和真实跨设备流程标记为通过。
