## 三项 Toy 适配

1. **横屏沉浸**：从开始/继续游戏、创建/加入房间及全屏按钮发起申请；先监听容器，再调用 `setContainerMode`，依据实际状态确认结果。使用容器 viewport 和 safeArea 调整画布、HUD、触摸区域与按钮；未确认或失败给出提示。普通浏览器继续使用原生全屏方式，SDK 加载失败不阻止游戏。
2. **生存报告**：死亡和通关界面可生成 720×960 的报告卡，包含位置、用时、磁带、击杀、步数、种子及死因。二维码由 Toy SDK 生成并加入图片，失败仍保留纯文字卡。图片 base64 长度限制在 2,000,000 字符以内。B站 App 可分享页面或保存相册，普通网页提供图片下载和可复制链接。
3. **联机邀请**：房主大厅可分享 `index.html?room=AB23` 形式的当前 Toy 相对链接或二维码。收件人打开后进入大厅、填好房间码，必须主动点击加入。房间仍使用原 PeerJS 联机，需要房主在线；Toy SDK 不提供信令或游戏传输。

报告链接采用 `index.html?report=...`，接收端检查字段和范围，只展示“玩家分享记录”，不认证成绩、不写入存档，也不根据链接自动开始新游戏。房间码限定为现有四位字符集。没有接入用户资料授权、云存档或排行榜。

## Toy 功能补强与验证

- 以用户提供的 `toy.d.ts` 作为编译契约，保存于 `src/types/toy.d.ts`；仅把异步加载期间的 `window.toy` 标为可选。
- 首页新增“分享游戏 / 跨设备打开”。该入口分享首页，不迁移存档；联机仍在房主大厅分享房间邀请。
- 首页、报告和房间邀请优先复制 `getQrCode` 返回的平台链接；平台链接未生成时明确标注当前页面链接。二维码支持下载和 App 相册保存；报告在 App 内仍保留下载入口，供相册权限拒绝时使用。
- 同目标二维码请求合并并缓存，缓存最多 16 项；失败可以重试。房间目标切换后，旧请求不会覆盖新二维码或链接。
- SDK 能力探测和分享操作均有超时保护；部分能力失败、脚本迟到、权限拒绝、限流时保留其他可用入口。
- `reports/toy-contract-verification.json` 包含真实官方 SDK 的 Web 能力与边界验证，以及模拟客户端故障测试；`reports/toy-verification.json` 包含游戏流程回归。详细边界见 `reports/TOY-VERIFICATION.md`。

## SDK 与兼容性

根据用户提供的 2026-09-09 Toy SDK 文档接入官方 HTTPS 脚本，异步加载，不新增运行依赖。所有 Toy 功能先查询 `isSupport`；分享与相册操作由按钮点击触发。`setContainerMode` 的 Promise 完成不作为模式切换成功依据。

原有 Google Fonts/少量远程插图、PeerJS 信令及 TURN 依赖仍在；此版本不是完全离线游戏。B站真实客户端的权限、二维码实际落地、横屏效果以及真实跨设备联机需要上传后验收。SDK 自动测试使用模拟客户端，不会向真实账号发送分享或保存相册。联机专项另用真实 PeerJS/WebRTC 建立临时测试房间，测试后关闭；它不能替代真实 B站 App 与跨网络双设备验收。

## 线上 Toy 跨网问题

已检查真实发布页；邀请参数和外部信令可用，同机两个隔离桌面客户端可在 Toy iframe 内直连。App 与电脑处于不同网络时，当前缺少已验证可用的 TURN，仍不能保证加入成功。新增 `public/multiplayer.json`（随包进入 dist）、HTTPS 临时凭据接口支持、大厅“联机诊断”和连接取消清理。当前默认配置没有 TURN；请勿把此补强包称为跨网问题已彻底修复。配置步骤见 `MULTIPLAYER-SETUP.md`，证据见 `reports/TOY-ONLINE-NETWORK.md`。
